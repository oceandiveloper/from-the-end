# Ablauf: Source → Content

Ziel jeder Source ist zweifach: (a) Kevin wendet sie selbst an (Practice, Audio zum Hören), (b) sie wird Content für From The End.

1. **Intake** (Workflow 1 bis 4): Source mit Transkript, Metadaten, Kanal. Kevins Notiz "Why this, right now?" ist das Briefing.
2. **Analyse** (Workflow 5): Key Points, Persönliche Relevanz, Abdeckung gegen bestehende Topics/Methods.
3. **Klassifizieren**: Domain, Moment, Framing (LoA/säkular) und Practice-Typ (on demand, täglich, einmalig).
4. **Entwurf**: Writer, danach Reviewer/Improver. Kurz/mittel/lang. Kritik des Reviewers im Thread sichtbar.
5. **Freigabe** in `#fte-approvals`: Skripttext lesen, "Freigeben" oder "Änderung" mit Freitext. Writer läuft mit Feedback neu, Schleife bis zur Freigabe. Alle Versionen und Feedback in Airtable.
6. **Produktion**: ElevenLabs → Bunny → Airtable → zuerst in Kevins eigener Nutzung.
7. **Veröffentlichung**: eigene Freigabe pro Kanal (App, YouTube, ...).

## Mitarbeiter im Hintergrund
- **Researcher**: scannt regelmäßig (YouTube-API, bekannte Kreatoren, Trends), schreibt Kandidaten mit Status "Proposed", wöchentliche Shortlist. Aus der Shortlist wählt Kevin.
- **Supervisor/Overseer**: täglicher/wöchentlicher Digest in `#fte-supervisor` (Erzeugtes, Wartendes, Hängendes, Kosten). Ziel: Auch bei einer Woche Urlaub entstehen neue Inhalte und Ideen.
- **Producer**: Audio, Video, Upload, nur nach Freigabe.
